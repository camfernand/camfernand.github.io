CASE STUDY

RAMP corporate card statement workflow.

I built a workflow to collect cardholder memos, code expenses, reconcile statements, and prepare files for Acumatica upload.

FOCUS
Corporate card accounting · AP / GL coding · Close controls
TOOLS / METHODS
JavaScript · HTML/CSS · SheetJS / ExcelJS · Acumatica workbook exports
APPLICATION
Manufacturing accounting and commercial operations

Why this needed work

Corporate-card statements require complete transaction capture, cardholder documentation, correct expense account and subaccount coding, reconciliation to the billed statement, and a structured ERP upload. Manual spreadsheet handoffs create opportunities for lost memos, coding drift, missing transactions and unsupported close totals.

What I built

I developed the RAMP Statement Processor as a four-stage workflow: import the statement, split and prepare cardholder statements, merge returned memo updates, code the GL and subaccounts, then create a consolidated statement workbook and a separate Acumatica import workbook. The application also supports merchant coding suggestions, exceptions, audit logging of memo merges, and work-in-progress recovery.

Checks I built in

  1. Preserve and classify source rows, including unassigned or account-level items, and surface import-count and amount exceptions rather than silently omitting them.
  2. Generate cardholder workbooks with missing-memo indicators and prepare messages for cardholders, while keeping human responsibility for sending and reviewing responses.
  3. Merge returned statements into the master, identify conflicts and unmatched rows, and retain a merge audit trail for the close file.
  4. Support detailed GL and subaccount coding, including split allocations and rules with explicit validation for missing or inconsistent values.
  5. Compare coded output to the independently entered billed statement amount plus redeemed cashback; require the billed amount and flag variances before export, with a documented operator confirmation path for mismatches.
  6. Produce separate Acumatica upload and consolidated supporting workbooks; the tool prepares files but does not automatically post a transaction to the ERP.

How it helps

Cardholder follow-up, coding, and reconciliation are handled in one process rather than several separate spreadsheet handoffs. The resulting files are still reviewed before they are uploaded to Acumatica.
