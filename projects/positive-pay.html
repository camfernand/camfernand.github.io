CASE STUDY

Bank Positive Pay File Processor.

I built a tool that turns ERP check-register exports into bank-format files, checking voids, duplicates, and totals before upload.

FOCUS
Treasury controls · AP disbursements · Audit trails
TOOLS / METHODS
Go · Standalone Windows executable · XLSX parsing · CSV validation
APPLICATION
Private-equity-backed manufacturing finance operations

Where errors can happen

Bank Positive Pay files require exact formatting, correct status filtering, and a reliable tie-out to issued checks. A malformed or duplicated record can create bank exceptions and rework.

What I built

I developed a self-contained Go-based processor that reads an ERP check register, isolates eligible closed checks, excludes voided check numbers, creates bank-format CSV files by check date and validates generated files against the source before completion.

Validations I added

  1. Reject duplicate active check numbers, invalid fields and nonpositive payment amounts.
  2. Exclude a check number entirely if any source row for that number is voided.
  3. Preserve check number formatting and produce fixed-decimal amounts with the required headerless CSV layout.
  4. Re-open output files and verify record count, date, and total against eligible source rows.
  5. Retain a run log, archive changed prior outputs and remove the source only after successful validation under the configured policy.

How it helps

The team gets a more consistent file to upload, and possible errors are flagged before the bank receives it. The actual bank upload remains a separate manual step.
